CODEX SKILL / 001

个人博客
撰写

把一次具体的问题解决过程，沉淀成学习者能够独立理解、复现和迁移的技术文章。

HUMANIN THE
LOOP双重审核
在 Codex 中调用$personal-blog-writing

WHY IT EXISTS

不是把聊天记录换一种排版，
而是把一次经验提炼成一种方法。

技能会从当前需求和相关历史对话中识别问题模式、诊断依据、验证方法与常见误区，同时主动移除真实内部域名、地址、凭据和一次性环境信息。

WORKFLOW / 06 STEPS

工作流

两个清晰的人工审批点，保证“同意写”永远不等于“同意公开”。

  1. 01
    提炼素材

    总结相关对话，区分事实、推断和经验建议。

  2. 02
    确认简报

    提出标题、受众、大纲、篇幅、约束与脱敏范围。

    审批一
  3. 03
    撰写初稿

    生成 published: false 的 Markdown，避免误发布。

  4. 04
    循环审核

    把反馈合入同一初稿，持续检查敏感信息。

  5. 05
    批准发布

    只有收到明确发布指令，才进入 Git 提交阶段。

    审批二
  6. 06
    构建验证

    发布到 GitHub Pages，等待工作流并验证文章链接。

GUARDRAILS

它会主动
守住什么？

01

隐私边界

默认清理公司名称、内部链接、真实 IP、个人路径、账号与凭据。

02

发布边界

审核意见不是发布许可；没有明确批准，就不会提交和推送。

03

验证边界

不虚构执行结果。构建失败时停止发布，修复后重新审核。

把踩过的坑，封装成下一次可以直接调用的能力。
